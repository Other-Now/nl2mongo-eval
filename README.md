# nl2mongo-eval

**An eval-driven experiment: can an LLM answer data questions by writing MongoDB aggregation pipelines, and do retrieval (RAG) or an agent with tools help enough to justify their cost?**

The output is a recommendation backed by measurements (see [`REPORT.md`](REPORT.md)), not a demo.

```
question ──► system under test ──► {"collection", "pipeline"} or refuse
               │ zero_shot : inferred schema + rules
               │ rag       : + BM25-retrieved worked examples & operator notes
               │ agent     : + tools (sample_documents, run_pipeline) and self-correction, ≤ 8 turns
               ▼
          guard (allowlist, no $out/$merge/JS, no secrets, 5 s, 1000 rows)
               ▼
          MongoDB as a read-only user ──► result rows
               ▼
          execution accuracy vs hand-written gold pipeline  +  failure taxonomy  +  cost/latency
```

## The eval set

There are **50 questions** on MongoDB's `sample_mflix` dataset (23.5k movies, 50k comments, 1.5k theaters). The questions are defined in [`eval/build_questions.py`](eval/build_questions.py).

| category | n | examples of what it tests |
|---|---|---|
| filter | 10 | array membership, `$all`, codes vs names ("California" is stored as `CA`) |
| group | 10 | `$unwind` before grouping; mixed-type fields (37 movies have a string `year`) |
| join | 8 | `$lookup`; non-unique titles (three movies are called *Titanic*); a denormalised count that disagrees with the real one |
| date | 8 | ranges, `$month`/`$dayOfWeek`, quarter boundaries |
| nested | 6 | positional paths (`cast.0`), `$size` on arrays that are sometimes missing |
| must refuse | 8 | password or JWT requests, and data that doesn't exist (ticket sales, budgets, ages) |

**Gold answers.**
- Every answerable question has a hand-written gold pipeline.
- [`eval/check_gold.py`](eval/check_gold.py) runs them all and rejects any top-N question with a tie at the cutoff.
- CI re-checks that every gold pipeline still returns the expected number of rows.

**Scoring is execution accuracy.**
- Run the model's pipeline and compare its rows with the gold rows. Field names are ignored and extra fields are allowed.
- The row count must match. Order is checked only when the question asks for it.
- No LLM judge is involved.
- For the 8 "must refuse" questions, only a refusal counts as correct.

## Safety

Safety is layered, and each layer is tested:
1. **Database user has the `read` role.** The server itself rejects inserts and `$out`; `tests/test_db.py` proves it.
2. **Stage allowlist.** `$out`, `$merge`, `$function`, `$accumulator` and `$where` are rejected at any depth, including inside `$facet` and `$lookup` sub-pipelines.
3. **Secrets.**
   - Any reference to `password` or `jwt` is blocked.
   - The `sessions` collection is off limits.
   - Results are redacted, because a `$lookup` into `users` would otherwise return password hashes.
4. **Limits:** `maxTimeMS` 5000 and 1000 rows. A test shows that a cross join is killed.

## Results

The full run is in progress. Tables will be generated by `summarize.py` into `results/summary.md` and discussed in `REPORT.md`.

- **Model:** Qwen3-4B-Instruct Q4_K_M on llama.cpp (Vulkan), on a 4 GB GTX 1050 with 30 of 36 layers on the GPU, at temperature 0.
- **Hosted model:** any OpenAI-compatible endpoint runs with `--base-url` and `--api-key-env`.

## Run it

```bash
pip install -r requirements.txt
mongod --dbpath ./db --auth                        # or: docker run -p 27017:27017 mongo:8.2
python data/load_mflix.py --bootstrap-admin        # pinned sample_mflix JSON + read-only user
python -m pytest                                   # 69 tests
llama-server -m Qwen3-4B-Instruct-2507-Q4_K_M.gguf --jinja -c 8192 --port 8081
python run_eval.py --system all --label qwen3-4b-q4 --model qwen3-4b --base-url http://127.0.0.1:8081/v1
python summarize.py                                # -> results/summary.md
```

## Layout

```
nl2mongo/guard.py      read-only safety checks + result redaction
nl2mongo/db.py         runs pipelines as the read-only user, with limits
nl2mongo/schema.py     schema inferred from 1000 sampled docs per collection (types, mixed-type shares)
nl2mongo/systems.py    zero_shot, rag, agent (tool loop)
nl2mongo/retrieve.py   BM25 over eval/examples.jsonl and eval/operator_notes.md
nl2mongo/score.py      execution-accuracy comparison
nl2mongo/taxonomy.py   automatic failure categories
run_eval.py            one model x N systems -> results/<system>__<model>.jsonl (resumable)
summarize.py           accuracy, per-category, failures, paired McNemar tests
eval/                  questions (source + generated JSONL), gold checker, RAG corpus
docs/NOTES.md          interview notes
```

## Not done (on purpose, to keep it to a 1–2 day build)

- **No vector database.** BM25 over about 30 documents stands in for Atlas Vector Search; only `BM25.top` would change.
- **No LangGraph.** The agent is a roughly 60-line tool loop, and every turn is in the trace.
- **No web UI.** It is a CLI plus JSONL results.
- **50 questions, not 100.** One question is 2 points, so the paired tests in `summarize.py` separate real differences from noise.
